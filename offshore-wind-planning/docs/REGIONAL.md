# Regional capacity-constrained selection

`run_regional(cfg)` runs the paper's Section 4.4 procedure after the baseline
has been generated by this repository. It does not use an archived result,
fixed grid list, shapefile result table, or bundled research data.

```matlab
cfg = release_config(struct('dataDir','/path/to/private/inputs', ...
                           'outputDir','/path/to/new/outputs'));
run_stage1(cfg);
run_stage34(cfg);
cfg.targetCapacitiesGW = [100 1500]; % choose the targets for your study
reports = run_regional(cfg);
```

The configuration defaults specify the paper's target sweep. Targets are
settings, not stored results. All input data and generated files remain
outside the source distribution. 
## Required inputs and software

- MATLAB and the Gurobi MATLAB interface with a valid license. The adapter
  uses base MATLAB, HDF5 support and the JVM for SHA-256. It does not require
  Python or Statistics and Machine Learning Toolbox.
- Parallel Computing Toolbox is optional. Serial execution is the default;
  setting `cfg.numWorkers` above one enables the original parallel
  revaluation path and requires that toolbox.
- `cfg.baselineFile`: the new baseline MAT, containing `results`,
  `baseline_meta`, and its exact `price_CNY_per_MWh` vector. Baseline metadata
  must certify all grids and candidate searches as complete. Partial or
  unsuccessful baselines are rejected.
- Sibling `checkpoints/grid_*.mat` files produced by `run_stage34`, each
  containing `record` and `checkpoint`. They are read one at a time, avoiding
  a full load of the large baseline results array.
- `cfg.compactWindFile`: the compact wind database generated by `run_stage1`,
  with `wind2023.grid_index`, `wind_speed_140m_mps` and
  `wind_direction_from_deg`. Hourly series have 8,760 entries. The original
  read-on-demand HDF5 loader is retained.
- `cfg.priceFile`: the same private source price file used for B0. Its SHA-256
  must match B0 provenance. The adapter uses the saved B0 8,760-hour vector;
  it does not independently convert leap-year prices or infer a missing tariff.
  The original B0 driver takes the first 8,760 values, which must be finite,
  under its source price policy. P44 retains its narrower, original strictly positive-price
  assumption: its zero-storage dispatch uses a positive-price analytical
  branch. A B0 produced with zero/negative prices is therefore rejected by
  P44 rather than silently extending that model.

The adapter retains only B0-positive-NPV grids, without assuming a particular
number of grids or embedding their IDs. Every retained record must contain
the turbine coordinates/count/capacity; original platform cost components;
OSS and collection-tree edges; fixed export and storage design; saved
financial and energy metrics; and the complete selected B0 candidate with
hourly dispatch. The field list and validation are in
`src/regional/prepare_regional_inputs.m`. These are generated model outputs,
not files included with this repository.

## Generated files and resume behavior

Within `cfg.regionalOutputDir`, `input_cache` contains regenerated geometry,
the cross-grid conflict graph, price vector and selected-candidate snapshots.
The small compatibility metadata/CSV files in `input_cache/baseline_snapshot`
are generated from the new B0; no historical result tables are imported.
`results/target_*GW` contains reports, selected/deleted turbine tables and
resume state. `cache` holds repaired-grid power, costs, dispatch and finances.

Preparation checks source signatures, file hashes, candidate completeness,
price consistency and baseline financial identities. Unchanged prepared
inputs can be reused. After changing B0, prices or wind inputs, choose a new
`regionalOutputDir`; old runs are preserved rather than overwritten or mixed.

## Scientific scope

The portfolio subproblem maximizes total NPV within the target capacity band
(552 MW excess tolerance), using integer whole-grid choices. Cross-grid
conflicts are resolved by the original B0 NPV/MW priority and grid-ID tie
rule. Previously retained turbines are protected during supplementary
selection. The overall selection/repair/supplement sequence is a heuristic;
solving an individual MILP does not certify a global optimum of that sequence.

For changed layouts, the original functions recalculate within-grid wakes,
hourly power, collection-tree flows/cable ratings and farm cost. OSS and
original cable routes are fixed. Deleted ancestor locations can remain
connection nodes with the original conservative support-facility cost proxy.
Export hardware, storage size and their costs remain fixed while dispatch is
re-optimized using the B0 farm-side revenue LP; shore losses are evaluated
afterward. Cross-farm wakes and shared export infrastructure are not modeled.

If the retained-layout capacity upper bound falls below a target, the run can
stop with a geometry-only failure report. Such a bound applies to that
retained path, not every possible regional layout. Uncomputed financial
metrics remain unavailable; they are not replaced with original B0 values.

All original numerical selection, spatial repair, power, cost, LP and
financial functions are preserved. Release changes are confined to paths,
input preparation and entry-point orchestration. The MATLAB spatial-bin
preparation routine implements the original closed-radius cross-grid pair
set, with a radius of `1694 - 1e-6` metres; same-grid pairs are excluded.
