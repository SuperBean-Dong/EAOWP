# Offshore wind planning: main research model

MATLAB implementation accompanying the research manuscript **“Cross-scale propagation of marine constraints in offshore wind planning: Buildable capacity, engineering feasibility, and delivered-shore value.”**

This repository contains the main model only. It connects exclusion-constrained farm geometry to turbine layouts, platform selection, internal collection-system design, export/storage coordination and capacity-constrained regional deployment.

**No input datasets or computed results are distributed.** A clean clone requires the private inputs described in [`data/README.md`](data/README.md). The repository does not include meteorological MAT/NetCDF files, shapefiles or their sidecars, electricity-price arrays, baseline results, checkpoints, manuscript figures or third-party solver binaries.

## Included workflow

| Entry point | Role |
|---|---|
| `run_stage1(cfg)` | 7D wake-aware turbine micrositing and site-adaptive platform selection; creates a Stage 1–2 master file. |
| `run_stage34(cfg)` | OSS/internal collection optimization, followed by B0 export/storage optimization; creates a baseline file. |
| `run_regional(cfg)` | Section 4.4 capacity-constrained selection, cross-grid spacing repair, supplementation and financial revaluation. |
| `check_release(cfg)` | Read-only checks for installed interfaces and locally supplied inputs; runs no optimization. |

The main baseline uses 12 MW turbines, 242 m rotor diameter, 7D spacing, the 2023 planning wind input and an effective storage purchase cost of **1043.82 CNY/kWh**. Configuration and solver budgets are recorded with newly generated outputs.

The package intentionally omits 9D/11D spacing sensitivity, high-storage-cost scenarios, S1–S6 ablations, wind/price sensitivities, meteorological preprocessing, figure production and historical repair/merge scripts.

## Requirements

- MATLAB with Mapping Toolbox (`shaperead`).
- Gurobi's MATLAB interface with a valid license.
- YALMIP for the collection-system MISOCP.
- Parallel Computing Toolbox only if parallel micrositing is enabled. The portable default is serial execution.
- The empty-candidate-library repair can use Gurobi or `linprog` from Optimization Toolbox; inspect its availability before running unusual geometries.

Third-party packages and licenses must be installed separately and added to the MATLAB path. No Python runtime is required by the portable main-model entry points.

The reported main experiments used MATLAB R2025b and Gurobi 13.0.1. Release syntax and limited portability checks are performed separately; solver versions, finite time limits and hardware can change attained incumbents and numerical results.

## Quick start

1. Download/clone this repository and open its root folder in MATLAB.
2. Install the dependencies and supply your own input data.
3. Configure paths and inspect readiness:

```matlab
cfg = release_config(struct( ...
    'dataDir', '/absolute/path/to/private_inputs', ...
    'outputDir', '/absolute/path/to/new_outputs'));
check_release(cfg);
```

4. Run the stages in order:

```matlab
run_stage1(cfg);
run_stage34(cfg);
run_regional(cfg);
```

No optimization is started merely by opening the repository or calling `release_config` / `check_release`. Each stage writes to the configured output/cache files and directories; explicit file-path overrides take precedence over the default output directory. **Stage 3/4 and the regional model consume outputs generated by the previous steps**, not bundled historical results.

For a short path/solver trial, restrict the grid interval first:

```matlab
cfg = release_config(struct('startIndex', 1, 'endIndex', 1));
run_stage1(cfg);
run_stage34(cfg);
```

Such a partial run cannot reproduce full-domain regional portfolios. Run the complete intended grid set before invoking the manuscript-scale regional targets. Preserve grid ordering across shapefile, meteorological columns and Stage 1–2 records.

## Configuration and reproducibility

- Paths are resolved from `release_config.m`. Directory overrides recalculate the default dependent filenames; explicit filename overrides take precedence.
- Resume is enabled by default. Keep the same scientific inputs and configuration when resuming. Use a new output directory when changing them.
- `collectionSolver = 'fast'` preserves the original main production strategy. `'solver_init'` explicitly selects the later solver-incumbent initialization variant. Both original core implementations are included; neither is relabelled as an identical rerun of the historical merged baseline.
- The historical final baseline combined main runs and targeted reruns. Recomputing from source under a different environment is a new model run; identical saved MAT files or identical finite-budget incumbents are not promised.
- The collection gap concerns the joint collection-cost plus shore-proxy objective. Regional selection and spacing repair use the retained-layout procedure, including a possible capacity-deficit termination; no global spatial-optimality certificate is implied.

See [`docs/STAGE1_INPUTS.md`](docs/STAGE1_INPUTS.md), [`docs/STAGE34.md`](docs/STAGE34.md), [`docs/REGIONAL.md`](docs/REGIONAL.md) and [`docs/RELEASE_SCOPE.md`](docs/RELEASE_SCOPE.md).

## Release validation

Packaging checks used MATLAB R2022a: syntax checks for all 47 MATLAB files,
configuration and missing-input checks, a synthetic one-turbine 8760-hour
Stage 3/4 run with resume/strategy-identity checks, and its hand-off to a
single-target regional run. Cross-grid pair preparation matched brute-force
MATLAB calculations and the original SciPy implementation on six synthetic
cases. Test inputs and outputs are not distributed. No real study grid was
recomputed during packaging, and these checks are not a full-domain rerun.
